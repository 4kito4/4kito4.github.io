## 1. NPUローカルAI環境

- 何か: AI PC の NPU（CPU/GPUと別の推論専用チップ）上で動くローカルAI・音声認識環境。クラウドに音声を送らず手元で完結
- 構成: **Lemonade Server**（ローカルLLM実行基盤、port 13305）+ **Qwen3-ASR**（音声認識、port 8081）
- 実測成果: **10秒の音声を約3.2秒で文字起こし**（2026-07-22 の高速化チューニング後。リアルタイム係数 約0.32）
- 意義: プライバシー（音声が端末外に出ない）/ オフライン動作 / NPU による省電力推論

### ビジュアル化指示
- 図A: パイプライン図 — [マイク音声] → [Qwen3-ASR（NPU）] → [テキスト] → [Lemonade ローカルLLM] → [応答]。「ここまで全部ローカル」の囲みを付ける
- 図B: 横棒比較 — 「音声の長さ 10秒」vs「処理時間 3.2秒」（比率が視覚で分かる2本バー、RTF 0.32 を添える）

## 2. intro-topic-bot

- 何か: Discord Bot。**表向きは「定期的にお題を投下する Bot」**。実際は #自己紹介 チャンネルの投稿から専攻・興味を **Gemini API** で読み取り、**雑談チャンネルが静かなタイミング**に「その人が話しやすいお題」をそっと投下する
- 設計思想: **ステルス** — 自己紹介を見ていることが投稿から一切分からないようにする（「見てる感」を出さない配慮設計）
- 実装: Python（uv 管理）/ Bot 権限は View Channels・Send Messages・Read Message History の**3つだけ**（最小権限）/ gemini-3-flash の無料枠で動作
- 例: 哲学専攻の自己紹介 → 雑談chに「記憶をすべて失っても、その人は同じ人だと思いますか？」

### ビジュアル化指示
- 図C: フロー図 — [#自己紹介] → (Gemini APIで興味抽出) → (お題生成) → (静けさ検知で待機) → [#雑談 へ投下]。「本人には見えない裏側」を点線囲みで
- コミュニティ文脈: Discord特別委員会の活動と地続きである旨を一言添える

## 3. 履修AI「course-navigator」

- 何か: 大学の履修選択を支援するAI。科目のつながり（前提関係・共通トピック）をグラフで持ち、納得感のある科目選びを助ける
- 体制: **Google AI Tech Hub 発の共同開発（3名）**。**Aki_Ha は UI／フロントエンド担当**。メンバー全員多忙のため本格始動前のフェーズ（正直に書く）
- 技術: FastAPI（Python）/ React 19 + Vite + TypeScript / **PostgreSQL（シラバス・あいまい検索）+ Neo4j（前提講義グラフ、GraphRAG 構想）** / Traefik / Docker Compose
- 動いているもの（疎通テスト実装済み）: シラバス登録 → あいまい検索 → **前提履修ロードマップ（矢印連結表示）** + 共通トピックによる関連講義サジェスト。未登録の前提講義はプレースホルダー自動同期
- GitHub: https://github.com/cyanosome/course-navigator （公開してよい）

### ビジュアル化指示
- 図D: 二層データ構造図 — PostgreSQL（シラバス表・検索）と Neo4j（科目ノード＋前提エッジのグラフ）が1つの検索結果にマージされる様子。グラフ側は「基礎数学 → 解析力学 → 量子化学」のような矢印チェーンのミニ図
- ステータス表記: 「共同開発・準備中（UI担当）」のような正直なフラグ
